FINDING: app/utils.py | `parse_money` uses binary float arithmetic (`int(float(raw) * 100)`), so common inputs lose a cent — `parse_money("12.34")` returns 1233 instead of 1234 — and it should use `Decimal` or `round()` instead.
FINDING: app/utils.py | `parse_money` truncates toward zero rather than rounding, so sub-cent inputs like `"0.009"` silently become 0 and negative amounts like `"-1.005"` round the wrong direction.
FINDING: app/utils.py | `parse_money` performs no validation or error handling: non-numeric input (`"$12.34"`, `""`, `None`) raises an uncaught `ValueError`/`TypeError`, and `"inf"`/`"nan"` raise `OverflowError`/`ValueError` from `int()`, so callers get exceptions instead of a documented failure mode.
FINDING: app/utils.py | `parse_money` accepts exponent notation (`"1e10"`) and unbounded values, producing arbitrarily large cent amounts with no range check on untrusted input.
FINDING: app/utils.py | `clamp` silently violates its contract when `low > high`: `max(low, min(high, value))` returns `low`, a value above the supposed upper bound, instead of raising for the invalid range.
FINDING: app/utils.py | `clamp` returns `low` for a NaN `value` (since all NaN comparisons are false), quietly converting invalid input into a plausible-looking number.
FINDING: app/utils.py | Neither `parse_money` nor `clamp` has any caller in the repository (confirmed via `callers_of` and a repo-wide grep), so the change adds dead code — if `pricing.py`/`api.py` were meant to route money parsing through `parse_money`, that wiring is missing and the truncating `int()` conversions remain duplicated in `app/pricing.py`.
FINDING: app/utils.py | Both new functions lack type annotations and `clamp` lacks a docstring, contrary to the project's Python style rules requiring annotated signatures.
FINDING: app/pricing.py | `apply_bulk_discount` uses `quantity > threshold` while its docstring says the discount applies when the order *reaches* `BULK_THRESHOLD`, an off-by-one that makes `tests/test_pricing.py::test_bulk_discount_applies_at_threshold` fail (`apply_bulk_discount(10, 100)` returns 1000, test expects 900); it should be `>=`.
FINDING: app/pricing.py | `apply_bulk_discount` returns `int(unit_cents * quantity * 0.9)` on the discounted path but a plain product on the other path, and truncates instead of rounding, so totals differ by a cent from the correctly-rounded value.
FINDING: app/pricing.py | `compute_total` requires three arguments (`quantity, unit_cents, tax_rate`) but `app/orders.py:8` calls it with two, so every `create_order` call raises `TypeError`.
FINDING: app/pricing.py | `compute_total` truncates the tax-inclusive amount with `int()` instead of rounding, systematically under-charging by up to one cent per line.
FINDING: app/pricing.py | The 0.9 bulk-discount factor is hardcoded while the threshold is configurable, so the discount rate cannot be changed via `SETTINGS` as the surrounding design implies.
