## Review

**Blast radius (graph):** `features/ledger_00/core.py` is imported by exactly one consumer — `consumers/worker_00/client_01.py` (`from features.ledger_00.core import resolve`). `format.py` and `audit.py` have no importers at all. `run_01` itself has no in-repo callers (leaf entry point).

**The substantive change** is in `core.py`: `LedgerRecord01.__init__` now stores the constructor argument as `self.amount_minor_units` instead of `self.amount_cents`. Nothing else in the change carries behavior — `format.py` and `audit.py` are byte-for-byte identical to the sibling `features/ledger_01/*` versions and are labeled "unchanged behaviour".

That rename is not propagated to the one consumer, so `run_01` raises `AttributeError` on every call.

FINDING: features/ledger_00/core.py | Renaming the record attribute from `amount_cents` to `amount_minor_units` was not propagated to `consumers/worker_00/client_01.py:8`, which still reads `record.amount_cents` and will now raise `AttributeError: 'LedgerRecord01' object has no attribute 'amount_cents'` on every `run_01` call.
FINDING: consumers/worker_00/client_01.py | `run_01` formats `record.amount_cents`, an attribute that no longer exists after the `core.py` rename, breaking the only consumer of `features.ledger_00.core.resolve`.
FINDING: features/ledger_00/core.py | No backward-compatible shim (e.g. an `amount_cents` property aliasing `amount_minor_units`, or a deprecation period) was added for what is a public attribute rename, so any out-of-repo/serialized consumer of `LedgerRecord01.amount_cents` breaks silently at runtime rather than at import time.
FINDING: features/ledger_00/core.py | The constructor parameter is still named `amount_cents` while the stored attribute is `amount_minor_units`, an inconsistent internal/external naming pair that makes the intended unit ambiguous at the call site.
FINDING: features/ledger_00/core.py | The rename to "minor units" implies a currency-agnostic unit but no conversion or currency field was introduced — the value is stored verbatim, so for zero-decimal currencies (e.g. JPY) or three-decimal currencies (e.g. KWD) the attribute name now misrepresents the magnitude it holds.
FINDING: features/ledger_00/core.py | The module-level factory is named `resolve`, an extremely generic name that collides with many unrelated `resolve` definitions in the repo (`services/svc_*/​*.py` with signature `(key, table)`, `features/tax_01/core.py` with `(amount_cents, quantity, rate_bps)`, `features/receipt_00/core.py`), inviting a wrong-import bug and defeating call-graph analysis — the graph tool refused `callers_of('resolve')` as too generic, so the rename's blast radius cannot be verified automatically.
FINDING: features/ledger_00/core.py | Sibling modules follow a `<domain>_total_<n>` factory naming convention (e.g. `ledger_total_16` in `features/ledger_01/core.py`), so `resolve` here is an unexplained deviation from the established pattern for the same record shape.
FINDING: features/ledger_00/core.py | `LedgerRecord01` performs no validation of `ident` or `amount_cents` (no type/None/negative checks) despite representing a financial amount, so malformed values propagate silently into ledger records.
FINDING: features/ledger_00/core.py | No type annotations on `LedgerRecord01.__init__` or `resolve` despite the repository's Python style requiring annotations on all function signatures, which also means a type checker cannot catch the `amount_cents` attribute break in the consumer.
FINDING: features/ledger_00/core.py | There is no test anywhere in the repository covering `LedgerRecord01`/`resolve` (no test files exist at all), so this attribute rename and its consumer breakage are entirely uncaught by automated verification.
FINDING: features/ledger_00/format.py | `describe_format` and `normalise_format` are dead code — nothing in the repository imports `features.ledger_00.format`, so this file adds unused surface area to the change with no behavioral justification.
FINDING: features/ledger_00/audit.py | `describe_audit` and `normalise_audit` are dead code — nothing imports `features.ledger_00.audit`, and the file is a byte-for-byte duplicate of the sibling `features/ledger_01/audit.py`, so it is unreachable copy-paste included in a change whose docstring admits "unchanged behaviour".
FINDING: features/ledger_00/audit.py | `normalise_audit` is character-for-character identical to `normalise_format` in `features/ledger_00/format.py` (`str(value).strip().lower()`), duplicated logic that should be a single shared helper rather than two divergence-prone copies.
FINDING: features/ledger_00/audit.py | `normalise_audit`/`normalise_format` coerce with `str(value)` unconditionally, so `None` silently becomes the string `"none"` and a numeric `0` becomes `"0"`, masking missing-value bugs instead of surfacing them.
FINDING: features/ledger_00/__init__.py | The package exports nothing and provides no re-export of `LedgerRecord01`/`resolve`, forcing consumers to import from the deep `features.ledger_00.core` path, which is exactly why the attribute rename could not be shielded behind a stable package-level API.
