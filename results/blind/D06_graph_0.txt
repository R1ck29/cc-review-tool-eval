Reviewed `app/repository.py` against its callers, config, models, and the DB layer.

FINDING: app/repository.py | The retry loop only re-queries when `row` is falsy, so it cannot recover from the transient failures retries exist for — a `sqlite3.Error` raised inside `db.fetch_order_row` propagates on the first attempt and skips every remaining attempt.
FINDING: app/repository.py | Retrying on a falsy row means a legitimately non-existent `order_id` is queried `MAX_RETRIES + 1` times (each opening a new SQLite connection) before returning `None`, wasting connections on a deterministic miss that will never succeed.
FINDING: app/repository.py | With `MAX_RETRIES = 0` in `app/config.py`, `attempts` is 1, so the retry loop is dead code as shipped and the "retrying per MAX_RETRIES" behaviour promised by the docstring never happens.
FINDING: app/repository.py | `get("MAX_RETRIES") + 1` passes no default, so a missing or `None`-valued `MAX_RETRIES` key raises `TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'` instead of falling back to a single attempt; a non-int value (e.g. `"3"` from env config) fails the same way.
FINDING: app/repository.py | `get_order` returns `None` for a missing order, but `orders.get_order_summary` immediately dereferences `order.id`, so a bad `order_id` surfaces as `AttributeError: 'NoneType' object has no attribute 'id'` rather than a not-found error.
FINDING: app/repository.py | `Order(*row)` maps columns positionally and silently depends on the exact `SELECT` column order in `db.fetch_order_row`; reordering or adding a column in that query yields a wrongly populated `Order` (e.g. `status` holding a discount) with no error, and a column-count change raises an opaque `TypeError`.
FINDING: app/repository.py | No retry delay/backoff between attempts, so if `MAX_RETRIES` is ever raised the loop hammers the database in a tight spin.
FINDING: app/repository.py | The `discount_pct` column is loaded straight into `Order.discount_percent` with no null/type handling, so a `NULL` discount produces `discount_percent=None` and blows up later arithmetic; the naming mismatch also leaves the pct-vs-fraction unit unvalidated.
FINDING: app/orders.py | `create_order` calls `pricing.compute_total(quantity, unit_cents)` but `compute_total` requires a third `tax_rate` argument, so every `POST /orders` raises `TypeError: compute_total() missing 1 required positional argument: 'tax_rate'`.
FINDING: app/serializers.py | `order_to_dict` reads `order.discount`, which does not exist on `Order` (the field is `discount_percent`), so serializing any order raises `AttributeError`.
FINDING: app/handlers.py | The handler subscribes to topic `"order_created"` while `events.publish_order_created` publishes to `DEFAULT_TOPIC = "order.created"`, so `on_order_created` is never invoked and the event is silently dropped.
FINDING: app/db.py | `fetch_order_row` closes the connection only on the success path; if `cur.execute` or `fetchone` raises, the connection leaks because `conn.close()` is not in a `finally` block or `with` statement.
FINDING: app/pricing.py | `apply_bulk_discount` uses `quantity > threshold` while the docstring says the discount applies "when the order reaches BULK_THRESHOLD units" — an off-by-one that denies the discount at exactly 10 units.
FINDING: app/pricing.py | `apply_bulk_discount` returns a truncated `int` on the discount path but the raw `unit_cents * quantity` product otherwise, so a float `unit_cents` yields a float subtotal and inconsistent rounding between the two branches.
FINDING: app/events.py | `publish` iterates the subscriber list without isolating failures, so one raising subscriber aborts delivery to all later subscribers, and a subscriber that calls `subscribe` on the same topic mutates the list mid-iteration.
FINDING: app/api.py | `create` indexes `payload["customerId"]`, `payload["quantity"]`, and `payload["unit_cents"]` with no validation, so a malformed request raises an unhandled `KeyError` (and the key naming is inconsistently camelCase vs snake_case).
FINDING: app/orders.py | `_normalise` assigns to a local named `STATUS_OPEN`, shadowing the module-level constant of the same name, which is misleading dead naming that reads as a mutation of the constant.
FINDING: app/tasks.py | `run_task` builds an attribute name from caller-supplied `name` and `getattr`s it off the `handlers` module, so any module-level attribute starting with `on_` is callable by external input with no allowlist.
